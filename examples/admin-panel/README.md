# Admin panel example

Use this brief to test operational information architecture.

- Sidebar destinations grouped by workflow, not database table.
- Search and structured filters kept distinct and visible.
- Compact table with identity, status, owner, updated time, and stable row actions.
- Selection count and bulk actions appear only after selection.
- Detail editing uses a focused page or sheet; a popover is reserved for short choices.
- Destructive actions state the exact target and consequence.

Acceptance test: keyboard users can search, filter, select rows, open a record, edit it, and return to the same list context without relying on hover.
